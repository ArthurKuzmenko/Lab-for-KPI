# ADR-0001: Нормалізація предметної області та структура зв'язків
* **Статус:** Прийнято
* **Дата:** 2026-10-16
## Контекст і проблема:
Необхідно спроектувати модель даних для сервісу оренди автомобілів, яка відповідатиме 3NF та не міститиме надлишкових фізичних сполучних таблиць.
## Розглянуті варіанти:
1. Зберігання історії оренди безпосередньо масивом всередині сутності `User`.
2. Використання чистої сполучної таблиці `User_Car` без власних атрибутів.
3. Виділення `Booking` як окремої асоціативної сутності з власними даними (дати, розрахована сума).
## Обґрунтування рішення:
Обрано Варіант 3. Оскільки процес оренди має власні унікальні атрибути (`start_date`, `end_date`, `total_price`), `Booking` є асоціативною сутністю. Це забезпечує відповідність 3NF та концептуальній чистоті ER-моделі.
