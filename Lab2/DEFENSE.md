# DEFENSE - Завдання 2 — Вимоги та Use Cases (EARS + user stories + Gherkin)
**Намір і критерії (1–2 речення):**
Розробити EARS-вимоги, User Stories та Use Case модель системи оренди авто. Критерії: ≥2 типів акторів, правильне використання include/extend, N:M трасування з непокритою вимогою та узгодженість із Завданням 1.
**Топ-3 розбіжності (вимоги ↔ модель) + коміт-виправлення:**
- **Помилка:** Вимога оплати згенерована без структури EARS.  
  *Виправлення:* коміт `feat(lab2): add EARS structured requirements`.
- **Помилка:** Промокод позначено як include замість extend.  
  *Виправлення:* коміт `feat(lab2): add mermaid use case diagram`.
- **Помилка:** Вимоги мали зв'язок 1:1 зі сценаріями.  
  *Виправлення:* коміт `docs(lab2): add traceability matrix N:M`.
**Ключове рішення — які альтернативи зважив і чому обрав цю (ADR):**
Виділено оплату як `include`, а промокод як `extend`. Докладно описано у `adr/0001-scenarios.md`.
**Перевірка - узгодженість із ER-моделлю Завдання 1:**
Актори та параметри сценаріїв відповідають сутностям `USER`, `CAR`, `OFFICE` та `BOOKING`.
